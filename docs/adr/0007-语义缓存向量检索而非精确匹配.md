# ADR-0007：语义缓存用「向量检索 + 精确短路」而非纯精确匹配

- **状态**：已采纳
- **日期**：2024-10
- **相关**：`src/devagent/models/vector_cache.py`、`src/devagent/models/gateway.py`、`tests/unit/test_vector_cache.py`

---

## 背景

多 Agent 系统里，同一个语义意图会产生大量**措辞不同**的模型调用：

```
"为用户列表接口增加分页能力"
"给用户列表接口加分页"
"users 列表需要分页支持"
```

原 `SemanticCache` 是**精确匹配**：把 `(role, content)` 全序列做 SHA-256，
哈希相同才命中。上面三条会被判为三个完全不同的请求，各调一次模型。

**代价是量级层面的**：缓存命中率从「3 次里命中 0 次」变成「3 次里命中 2 次」，
省下的是两次完整的模型调用。这不是边际优化。

同时要保留精确匹配作为**默认**：它零依赖、零额外调用，
且是所有部署都能走通的路径。

## 决策

新增 `VectorSemanticCache`，实现「**精确短路 + 向量近邻**」的两级检索：

```
查询 ─→ 精确哈希命中？
        ├─ 是 → 直接返回（零成本）
        └─ 否 → 计算查询向量 → 在候选桶内找最高余弦相似度
                                ├─ ≥ 阈值 → 命中
                                └─ < 阈值 → miss
```

配置开关 `DEVAGENT_CACHE__SEMANTIC`，**默认 `false`**（即沿用精确匹配）。

## 备选方案与权衡

### 方案 A：保持纯精确匹配，不做语义检索（**否决**）

最省事，也是"够用"的选择。

**为什么否决**：它把多 Agent 系统里最典型的成本来源（同一意图的多次表述）
完全放弃了。这个项目的卖点之一是上下文工程与成本控制，
而模型调用成本恰恰是大头 —— 在能低成本解决的问题上不做优化，
会让"成本控制"这个说法缺乏说服力。

### 方案 B：用欧氏距离而非余弦（**否决**）

两者对归一化向量等价，实现难度也相近。

**为什么否决**：embedding 的**模长**与语义相关性无关，只与文本长度、
词频高低有关。「分页」与「请帮我给这个用户列表接口增加一个分页的功能」
语义几乎相同，但向量模长差很多 —— 欧氏距离会把它们判为不相似。

余弦把模长归一化掉，只比较方向，这才是语义相似度该有的度量。

### 方案 C：引入 ANN 库（FAISS / hnswlib）做近似最近邻（**否决**）

教科书上的正确答案，工业界大规模向量检索的标配。

**为什么否决**：

- **规模不匹配**。缓存上限 512 条，512 × 1024 维的暴力点积约 **0.5ms**，
  相比一次模型调用（数百毫秒到数秒）可以忽略。ANN 解决的是
  百万级以上的检索问题，用在这里是**用重武器打蚊子**。
- 引入编译型依赖会破坏"`pip install` 即可用"的体验，也拖慢 CI。
- ANN 是**近似**的：它可能漏掉真正的最近邻。对本场景而言，
  漏掉一次命中只是少省一次 token，而换来的是调参负担与一个**非确定性**
  组件 —— 收益与代价不匹配。

**什么时候该改回 ANN**：缓存条目数超过 10⁴ 量级，或维度显著更高。
届时应把它做成可插拔的 `VectorIndex` 协议，而不是现在就为未来的规模买单。

### 方案 D：不做分桶，全局检索（**否决**）

省掉分桶代码，理论上命中率更高（同一问题问不同模型也能互相命中）。

**为什么否决**：向量相似的**前提**是"同一个问题被问给同一个模型、
同样的温度"。跨模型召回会返回「看起来相似但来自别的模型」的结果 ——
这在需要模型可复现性的场景（回归测试、评测对照）里是**正确的灾难**：
你以为在复现旧结论，实际上拿到的是另一个模型的输出。

保留为选项（`model_filter=False`），但默认关闭。

### 方案 E：把 `get`/`put` 改成 async（**否决**）

最"干净"的做法：既然要算 embedding，就让整个接口异步。

**为什么否决**：`get`/`put` 是精确匹配路径的接口，而精确匹配**不需要任何 I/O**
—— 它只是一次字典查找。把它变成 `async def` 会让那条路径也付出协程开销，
并让所有直接使用它的测试与调用点被迫改成异步。

实际采用的是**双接口**：`get`/`put` 保持同步（精确匹配），
新增 `aget`/`aput` 承担异步（向量检索）。网关用
`_cache_get`/`_cache_put` 适配，并在其中做**显式的 `isinstance` 判断** ——
因为两条路径的语义与成本差异显著，调用方需要知道自己在走哪条。

这与 [ADR-0006](0006-任务存储同步协议薄异步适配.md) 是同一种取舍：
**把差异集中在一处适配，而不是扩散到所有调用方。**

### 方案 F：用真实 embedding 服务做测试（**否决**）

**为什么否决**：测试会变得依赖外部 API（网络、配额、费用），
且 embedding 模型版本变化会让断言不稳定。

本文件的分工是明确的：

- **本模块的单测**（`test_vector_cache.py`）用**确定性的假 embedder**
  验证**判定逻辑**：阈值、分桶、降级、淘汰；
- **embedding 质量**（能否把「分页」与「分页支持」判为相似）属于
  **模型能力**，不该由单测断言，也无法通过单测保证。

因此测试里的阈值是 0.8 而不是产品默认的 0.92 —— 字符袋向量的余弦
有确定的上界关系（`|A∩B| / sqrt(|A|·|B|)`），「用户分页」vs「用户分页列表」
约为 0.816。这是假 embedder 的固有特性，不影响判定逻辑的验证。

## 后果

### 正面

- 措辞不同的重复请求可命中，省下一次完整模型调用
- `/api/v1/cache` 分别报告 `exact_hits` / `semantic_hits`，
  **升级带来的增量是可度量的** —— 而不是"感觉快了一些"
- 默认关闭，行为与升级前完全一致（有专门的一致性测试守护）
- 嵌入失败自动降级为精确匹配，缓存不会成为可用性单点

### 负面 / 技术债

- 开启后每次未命中多一次嵌入调用（延迟 + 成本）。**这是净亏损的场景真实存在**
  （请求差异大、几乎不重复），因此 `semantic_share` 必须被监控，
  前端会把"语义命中为 0"明确标成需要关闭的信号
- 向量桶是内存结构，多实例部署时各自独立（与任务存储不同，这里**不做持久化**是
  有意的：缓存的跨实例一致性收益低，而失效逻辑复杂）
- 线性扫描在条目数超过 10⁴ 时需要改造成 ANN（见方案 C 的触发条件）

### 一个反直觉的细节：只嵌入最后一条消息

`_query_text` 只取最后一条消息，而不是把整段对话拼起来嵌入。

理由：前面的消息多为**稳定的系统提示与历史**，把它们拼进来会让
所有请求的向量都向"平均语义"**塌缩**，反而降低区分度 ——
两个不同的需求因为共享同样的长系统提示而变得"相似"。

这条有专门的测试守护（`test_embedding_uses_last_message`）。
