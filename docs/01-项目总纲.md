# 项目目标与路线图

DevAgent 是用于研究多 Agent 协作和上下文工程的研发助手。输入自然语言需求，输出结构化规格、技术方案、代码产物、测试证据和逐条验证反馈。当前版本的交付物是代码文本，补丁还没有应用到实际工作区。

## 项目目标

- 在有限上下文预算中选择相关内容、控制冗余并保护约束。
- 用明确的产物依赖连接各 Agent，避免靠猜测接口协作。
- 把执行与验收分开，独立验证输入中排除作者的效果声明。
- 记录所有模型调用的用量，通过熔断、反馈重试和检查点控制失败成本。
- 通过可复现评测比较质量与费用，不用未测量的数字宣称收益。

## 当前实现入口

架构、模块和数据流集中在 [架构说明](06-架构说明.md)；运行和配置见 [README](../README.md)；开发与质量门禁见 [贡献指南](../CONTRIBUTING.md)。技术选择及备选方案在 [ADR](adr/README.md) 中维护。实际能力边界见 [质量与已知限制](07-质量与已知限制.md)。

后端是 Python / FastAPI，前端是原生 ES Module / CSS，无构建依赖。模型网关支持多供应商；任务存储支持内存与 SQL；事件通道是进程内 EventBus + SSE；测试沙箱支持本地进程与 Docker。React、Redis Stream、自动 Git 操作和持久化检查点不属于当前已交付能力。

## 后续优先级

| 顺序 | 工作 | 完成标准 |
| --- | --- | --- |
| 1 | 受控补丁应用 | 校验路径和补丁，在独立工作区应用；测试明确针对改动后的代码；失败可回滚 |
| 2 | 持久化恢复 | 检查点保存规格、产物及输入版本；跨进程重启可恢复且拒绝陈旧输入 |
| 3 | 真实模型评测 | 固定数据集与模型配置，记录成功率、需求覆盖、费用和时延，与基线对照 |
| 4 | 大仓库与并发验证 | 基线快照复制成本、并发测试和事件流压测有可重复测量 |
| 5 | Reviewer 接线 | 明确自动审查触发条件、输入和费用，配置开关与实际行为一致 |

这些是待实现工作，不是既有能力承诺。是否采用新的存储、检索或前端框架，应由实际规模与测量结果决定。
