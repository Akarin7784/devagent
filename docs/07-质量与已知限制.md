## 验证方法

安装 `pip install -e ".[dev,db]"` 后执行：

```bash
python -m pytest -q
python -m ruff check src tests scripts
python -m ruff format --check src tests
python -m mypy src
python scripts/demo_smoke.py
```

前端运行 `make web-check`。Windows 没有 make 时使用 PowerShell：

```powershell
python scripts/export_web_contracts.py
Get-ChildItem web/*.test.js | ForEach-Object { node $_.FullName; if ($LASTEXITCODE) { throw "前端测试失败" } }
```

若本地虚拟环境尚未以 editable 模式安装项目，可临时设置 `$env:PYTHONPATH='src'`。Windows 设置 `$env:PYTHONIOENCODING='utf-8'` 可避免中文输出受到控制台代码页影响。使用虚拟环境中的 Python 执行命令。

## 当前能力边界

- **尚未应用 Coder 补丁。** 代码产物是 diff 或片段，传递给下游与验证器，但未应用到测试目录。测试执行的是基线快照。默认基线为空，测试可能无法导入被测代码。基线测试通过不能证明本次改动正确，也不能把任务 succeeded 解读为代码已经发布或合并。
- **默认检查点在内存中。** 同一进程内可复用已验证节点和产物；进程重启后不会自动恢复。SQL 任务存储不等于检查点持久化；旧检查点若缺少产物会重跑节点。
- **Reviewer 不会在默认主链路自动追加。** 它已注册，可作为架构产出的 DAG 节点执行；不要将 `enable_reviewer` 解释成自动审查能力。
- **本地沙箱不提供容器安全边界。** 网络、内存等策略只有 Docker 后端能强制。生成测试在独立快照中执行，但本地进程仍具有宿主用户权限，详见 [安全策略](../SECURITY.md)。
- **验证结论仍来自模型。** 严格解析和材料隔离能阻止特定失效模式，不能保证模型判断正确；尚未通过真实模型评测得到成功率或成本收益数据。
- **快照成本与基线大小有关。** 每次测试复制基线，排除虚拟环境、Git 元数据、常见缓存、环境密钥文件和符号链接；大仓库需要后续引入受控文件选择或只读基线挂载。

## 测试整理原则

同一函数的输入差异用参数化维护，例如 pytest 摘要、取消时机、验证输出格式；真实沙箱测试与替身测试分别守住执行行为和错误分支。移除仅凭手工干净输入证明“隔离成功”的测试，由检查真实 Coder/Verifier 输入的集成用例覆盖。历史回归按保证保留，避免为了减少文件数量删除不同失效场景。
